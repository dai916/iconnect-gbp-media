# Claude / 生成AI由来の初診相談予約を最大化する（LLMO）実装キット

アイコネクト大森矯正歯科に「Claudeで検索して来ました」という初診相談患者が毎月数人いる。
この流入を計測し、意図的に増やすための **実装用アセット一式** です。

- このリポジトリは公開です。ここに置くのは **公開されても問題ない計画・テンプレート・計測ツール** のみ。
  認証情報、患者情報、予約データは一切置かないこと（APIキーは環境変数で渡す）。
- 事実（住所・電話・料金・診療時間）は院内で確認してから使うこと。テンプレート内の `【要確認】` は必ず埋める。

## 戦略の要約

Claude は「複数ソースで一致する事実」を持つ医院を選び、確信が持てないと名前を出さない。
検索インデックスは Brave、地図情報は Google Maps / Places。専用クローラー（Claude-SearchBot / Claude-User）が
robots.txt で拒否されていると引用されない。

勝ち筋は次の4点。

1. 医院の事実が全ネット上で一貫している（NAP統一）
2. サイトが「質問に一文で答えられる」構造（FAQ・料金・限定解除4要件・構造化データ）
3. 第三者の裏取りがある（Googleレビュー、まとめ記事、学会、取材）
4. AI経由の人が迷わず予約できる導線（無料初診相談・24時間WEB予約が最初の画面にある）

そして **最初に計測を入れる**。これがないと「毎月数人」が増えたか判定できない。

## フォルダ構成

| フォルダ | 内容 | 担当の目安 |
|---|---|---|
| `01-measurement/` | 問診票の追加項目、GA4の設定手順、固定プロンプト20本、AI言及率の自動計測ツール | 院長 / Web担当 |
| `02-website/` | robots.txt・llms.txt の例、JSON-LD テンプレート、FAQ草案、ページ点検表 | Web制作会社 |
| `03-listings/` | ポータル・地図サービスの NAP 統一チェックリスト | 受付 / Web担当 |
| `04-gbp/` | 投稿本文の書き方、Q&A欄の整備案 | GBP投稿担当（`iconnect-gbp` 側） |
| `05-compliance/` | 医療広告ガイドライン・ステマ規制の観点でやらないこと | 全員 |

## 90日ロードマップ

| 期間 | やること | 完了条件 |
|---|---|---|
| 第1〜2週 | 問診票に「AIに聞いた」を追加。GA4に AI Referral チャネル作成。ベースライン計測（`measure_ai_mentions.py` を1回実行）。NAP統一チェック開始 | ベースラインの言及率と競合リストが記録されている |
| 第3〜8週 | FAQ 30問以上を公開。料金ページに限定解除4要件を揃える。JSON-LD と robots.txt を反映。院長プロフィールに学会・受賞を年次で記載 | `02-website/page-checklist.md` が全項目チェック済み |
| 第9〜12週 | まとめ記事への掲載申請、レビュー運用の定着、GBP Q&A整備。2回目の計測 | 言及率・AI Referral 予約数がベースラインと比較されている |

## KPI（月次）

- AI言及率：固定プロンプト20本のうち自院名が出た本数（Claude / ChatGPT / Gemini 別）
- AI Referral 予約数：GA4 で参照元が claude.ai / chatgpt.com / perplexity.ai / gemini.google.com の予約完了数
- 問診票で「AIに聞いた」を選んだ初診相談数（および AI 名の内訳）
- 引用された自院URL・競合URLの一覧（どのページが効いているか）

国内の歯科9院の支援事例では、言及率が平均9%から34%へ改善し、AI経由の新患予約が増えたと報告されている。
効果が来院数に現れるまでは実装後6か月程度が目安。
